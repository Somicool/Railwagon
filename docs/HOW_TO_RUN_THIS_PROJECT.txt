           Railway Wagon Image Deblurring & OCR Inspection System
================================================================================

PROJECT OVERVIEW:
-----------------
This is a comprehensive railway wagon inspection system that uses deep learning
and classical computer vision to:
1. Deblur images/videos captured from moving trains
2. Enhance low-light conditions
3. Extract wagon numbers using OCR
4. Process live video feeds from mobile cameras (DroidCam)
5. Detect motion to trigger automated capture

The system combines:
- MIMO-UNet/MIMO-UNetPlus for image deblurring
- Temporal fusion for multi-frame enhancement
- Classical CV techniques for text detection
- EasyOCR/Tesseract for wagon number recognition
- Motion detection for automated triggering

- Python 3.8 or higher

- DroidCam app (for mobile camera streaming)

----------------
See requirements.txt:

- torchvision>=0.10.0
- opencv-python>=4.5.0

- easyocr (for OCR)
- pytesseract (alternative OCR)

--------------------------------------------------------------------------------
USE CASE 1: DEBLUR A SINGLE IMAGE
--------------------------------------------------------------------------------

COMMAND:
    python run_deblur.py --input blurry_image.jpg --output sharp_image.jpg

PARAMETERS:
    --input, -i      : Path to blurry input image
    --output, -o     : Path to save deblurred result
    --weights, -w    : (Optional) Custom weights file
    --device         : cuda or cpu (default: cuda)

EXAMPLE:
    python run_deblur.py -i test_video.mp4 -o deblurred.jpg

OUTPUT:
    - sharp_image.jpg (deblurred result)

WHEN TO USE:
    - Quick deblurring of single images
    - Testing model performance
    - Preprocessing for further analysis

--------------------------------------------------------------------------------
USE CASE 2: TRAIN OR FINE-TUNE THE MODEL
--------------------------------------------------------------------------------

A. FINE-TUNE ON CUSTOM DATASET (Recommended for wagon images)
--------------------------------------------------------------
COMMAND:
    python train.py

CONFIGURATION (edit train.py):
    DATA_ROOT = 'LOL_BLUR'  # or 'train' for wagon dataset
    PRETRAINED_WEIGHTS = 'weights/mimo_unetplus_gopro_trained.pth'
    IMAGE_SIZE = 256
    BATCH_SIZE = 2          # Reduce if GPU memory issues
    LEARNING_RATE = 1e-5    # Low LR for fine-tuning
    NUM_EPOCHS = 30

OUTPUTS:
    weights/lol_epoch_10.pth    # Checkpoint at epoch 10
    weights/lol_epoch_20.pth    # Checkpoint at epoch 20
    weights/lol_epoch_30.pth    # Final checkpoint
    weights/lol_best.pth        # Best model (use this!)

TIME ESTIMATE:
    - Per epoch: 2-4 minutes
    - Total (30 epochs): 60-120 minutes

MONITOR GPU:
    nvidia-smi -l 1             # Updates every second

B. TRAIN FROM SCRATCH (For GoPro dataset)
------------------------------------------
Edit train.py:
    DATA_ROOT = 'GOPRO_Large'
    NUM_EPOCHS = 70
    PRETRAINED_WEIGHTS = None   # Start from scratch

TIME ESTIMATE: 8-16 hours

WHEN TO USE:
    - Fine-tuning: Adapt pretrained model to your specific use case
    - From scratch: Creating completely new model

DOCUMENTATION: See FINETUNING_GUIDE.md, GOPRO_TRAINING_GUIDE.md

--------------------------------------------------------------------------------
USE CASE 3: PROCESS VIDEO WITH COMPLETE PIPELINE
--------------------------------------------------------------------------------

COMMAND:
    python run_video_pipeline.py VIDEO_FILE MODEL_WEIGHTS [OPTIONS]

FULL EXAMPLE:
    python run_video_pipeline.py train_video.mp4 weights/gopro_best.pth \
        --output video_results \
        --fps 5 \
        --window 3 \
        --ocr easyocr \
        --confidence 0.3 \
        --device cuda

PARAMETERS:
    VIDEO_FILE       : Path to input video (MP4)
    MODEL_WEIGHTS    : Path to deblurring model (.pth)
    --output         : Output directory (default: results)
    --fps            : Frame extraction rate (default: 5)
    --window         : Temporal fusion window 3-5 (default: 3)
    --ocr            : OCR engine: easyocr or tesseract
    --confidence     : OCR confidence threshold 0.0-1.0
    --device         : cuda or cpu

PIPELINE STAGES:
    1. Extract frames from video at specified FPS
    2. Deblur each frame using MIMO model
    3. Extract wagon number bands (middle 40-60% of image)
    4. Fuse multiple frames temporally (reduces noise)
    5. Enhance text regions (CLAHE + sharpening)
    6. Run OCR to extract wagon numbers
    7. Save results with organized folder structure

OUTPUT STRUCTURE:
    results/
    ├── 1_raw_frames/           # Original video frames
    ├── 2_enhanced_frames/      # Deblurred frames
    ├── 3_band_frames/          # Wagon number regions
    ├── 4_fused/                # Temporally fused images
    ├── 5_enhanced_text/        # OCR-ready enhanced text
    ├── 6_ocr_results/          # OCR visualizations
    ├── ocr_results.json        # All detected wagon numbers
    └── pipeline_summary.txt    # Processing statistics

TIME ESTIMATE:
    - ~1-2 seconds per frame (GPU)
    - 30-second video at 5 FPS = ~2-5 minutes total

WHEN TO USE:
    - Processing recorded railway videos
    - Extracting wagon numbers from footage
    - Batch analysis of multiple trains

DOCUMENTATION: See VIDEO_PIPELINE_README.md

--------------------------------------------------------------------------------
USE CASE 5: MOTION-TRIGGERED CAPTURE
--------------------------------------------------------------------------------

COMMAND:
    python motion_gate_droidcam.py

Or run the batch file:
    RUN_MOTION_GATE.bat

FEATURES:
    - Monitors camera feed for motion
    - IDLE state until train detected
    - ACTIVE state during train passage
    - Automatically saves frames when train present
    - Background subtraction for robust detection

CONFIGURATION (edit motion_gate_config.py):
    DROIDCAM_URL = "http://192.168.1.6:4747/video"
    MOTION_THRESHOLD = 35.0      # % of pixels that must change
    MIN_CONTOUR_AREA = 15000     # Minimum object size
    FRAMES_TO_CONFIRM_TRAIN = 25 # Confirmation frames

STATES:
    LEARNING   → First 60 frames: Learning background
    IDLE       → Monitoring for motion (no capture)
    DETECTING  → Confirming train (25 consecutive frames)
    ACTIVE     → Capturing frames + processing
    IDLE       → Train passed, waiting for next

CONTROLS:
    - Press 'q' to quit
    - Press 'r' to reset background model

OUTPUT:
    motion_gate_output/
    ├── captured_frames/   # Frames during ACTIVE state
    └── debug/            # Motion masks and diagnostics

WHEN TO USE:
    - Automated railway monitoring
    - Hands-free operation
    - Reducing storage (only saves when train present)

DOCUMENTATION: See MOTION_GATE_README.md, MOTION_DETECTION_GUIDE.md

    ├── cropped_text_region.png     # Original crop

RESULTS:

    - +178% text contrast

WHEN TO USE:

--------------------------------------------------------------------------------
USE CASE 8: TEMPORAL FUSION (Multi-Frame Enhancement)
--------------------------------------------------------------------------------

COMMAND:
    python temporal_fusion_wagon.py

FEATURES:
    - Combines 3-5 consecutive frames
    - Phase correlation for alignment
    - Median or max-gradient fusion
    - Reduces blur and noise

METHODS:
    - Median Fusion: Robust to outliers
    - Max-Gradient Fusion: Preserves sharpest edges

WHY IT WORKS:
    Across multiple frames, blur varies! Temporal fusion recovers
    edges lost in individual frames by combining complementary
    information from multiple time points.

WHEN TO USE:
    - Video sequences with motion blur
    - Enhancing text readability
    - Reducing noise in captured frames

DOCUMENTATION: See TEMPORAL_FUSION_GUIDE.md

================================================================================
                      TROUBLESHOOTING GUIDE
================================================================================

PROBLEM: CUDA out of memory
SOLUTION:
    - Reduce BATCH_SIZE in train.py (try 1 or 2)
    - Use smaller images (IMAGE_SIZE = 128 or 192)
    - Close other GPU-using applications
    - Use CPU: --device cpu (slower but works)

PROBLEM: Camera won't open
SOLUTION:
    - Check DroidCam IP address in droidcam_config.py
    - Test connection: python test_droidcam.py
    - Try different camera indices: test_both_cameras.py
    - Ensure phone and PC on same WiFi

PROBLEM: Model weights not found
SOLUTION:
    - Check weights/ folder exists
    - Verify file name matches exactly
    - Download pretrained weights if needed
    - Use correct path: weights/gopro_best.pth

PROBLEM: Poor OCR results
SOLUTION:
    - Ensure image is deblurred first
    - Try wagon text enhancement script
    - Lower confidence threshold (--confidence 0.2)
    - Use temporal fusion for better quality
    - Check image is in focus

PROBLEM: Training too slow
SOLUTION:
    - Verify GPU is being used: nvidia-smi
    - Increase BATCH_SIZE if memory allows
    - Reduce IMAGE_SIZE (256 → 192)
    - Use NUM_WORKERS > 0 in train.py

PROBLEM: Import errors
SOLUTION:
    - Activate virtual environment
    - Install missing packages: pip install [package]
    - Reinstall requirements: pip install -r requirements.txt

PROBLEM: Motion detection too sensitive
SOLUTION:
    - Increase MOTION_THRESHOLD in motion_gate_config.py
    - Increase MIN_CONTOUR_AREA
    - Increase FRAMES_TO_CONFIRM_TRAIN
    - Press 'r' to reset background model

FULL TROUBLESHOOTING: See LIVE_TROUBLESHOOTING.md

================================================================================
                    PERFORMANCE OPTIMIZATION
================================================================================

GPU OPTIMIZATION:
-----------------
1. Use CUDA-enabled PyTorch
2. Increase batch size (if memory allows)
3. Use mixed precision training (future enhancement)
4. Monitor GPU usage: nvidia-smi -l 1

CPU FALLBACK:
-------------
All scripts work on CPU but are slower:
    - Use --device cpu
    - Reduce buffer sizes
    - Process fewer frames

SPEED VS QUALITY:
-----------------
Fast processing:
    - buffer_size=1 (no temporal fusion)
    - Lower FPS (fps=3)
    - Smaller images (IMAGE_SIZE=192)

Best quality:
    - buffer_size=5 (more temporal fusion)
    - Higher FPS (fps=10)
    - Larger images (IMAGE_SIZE=256)

================================================================================
                        COMMON WORKFLOWS
================================================================================

WORKFLOW 1: PROCESS EXISTING VIDEO
-----------------------------------
1. Prepare video file (MP4 format)
2. Ensure model weights in weights/ folder
3. Run: python run_video_pipeline.py video.mp4 weights/gopro_best.pth
4. Check results/ folder for outputs
5. Review ocr_results.json for detected wagon numbers

WORKFLOW 2: LIVE MONITORING SETUP
----------------------------------
1. Setup DroidCam on phone
2. Update IP in droidcam_config.py
3. Test: python test_droidcam.py
4. Run: python motion_gate_droidcam.py
5. Monitor output in motion_gate_output/

WORKFLOW 3: TRAIN CUSTOM MODEL
-------------------------------
1. Prepare dataset in train/ folder
2. Edit train.py configuration
3. Activate venv: .\venv\Scripts\Activate.ps1
4. Run: python train.py
5. Wait ~2-4 hours for fine-tuning
6. Use weights/lol_best.pth for inference

WORKFLOW 4: BATCH PROCESS IMAGES
---------------------------------
1. Place images in input/ folder
2. Create batch script:
    for %%f in (input\*.jpg) do (
        python run_deblur.py -i "%%f" -o "output\%%~nf_deblurred.jpg"
    )
3. Run batch script
4. Check output/ folder

WORKFLOW 5: ENHANCE DIFFICULT TEXT
-----------------------------------
1. Deblur image: python run_deblur.py -i blur.jpg -o enhanced.png
2. Detect text: python detect_and_enhance_wagon_text.py --input enhanced.png
3. Run OCR: python run_ocr_wagon.py
4. Check wagon_text_results/ for enhanced text
